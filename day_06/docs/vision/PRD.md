# Dungeon Crawler: Console Descent - Product Requirements Document

## 1. Обзор продукта

**Название:** Dungeon Crawler: Console Descent  
**Платформа:** Windows (первичная), кросс-платформенность возможна через .NET  
**Технологии:** C# (.NET 10+), SadConsole, Lua (для модификаций)  
**Тип:** Пошаговая консольная roguelike RPG с упрощёнными механиками D&D 3.5  
**Статус:** Начальная фаза разработки  

**Цель:** Создать доступную roguelike игру с глубиной D&D-механик и современным интерфейсом.

## 2. Функциональные требования

### 2.1. Геймплейные системы

#### 2.1.1. Движение и исследование
- **Пошаговое движение** по сетке 60x30
- **Процедурная генерация** уровней через клеточные автоматы
- **Фог войны** (туман войны) — открытие карты по мере движения
- **Взаимодействие с объектами** (сундуки, двери, алтари)
- **Обнаружение ловушек** через пассивное восприятие

#### 2.1.2. Боевая система (D&D 3.5 Lite)
- **Бросок атаки:** 1d20 + модификатор атаки vs Класс Брони цели
- **Урон оружия:** 1d6/1d8 + модификатор силы/ловкости
- **Спасброски:** 1d20 + соответствующий модификатор vs Сложность
- **Класс Брони (AC):** 10 + модификатор ловкости + бонус доспеха
- **Инициатива:** d20 + модификатор ловкости (пошаговый порядок)

#### 2.1.3. Система персонажа
- **Характеристики:** Сила, Ловкость, Телосложение, Интеллект, Мудрость, Харизма
- **Распределение очков:** 27 очков на старте (по правилам D&D 5e упрощённо)
- **Уровни и опыт:** Получение опыта за победу над монстрами
- **Прогрессия:** Увеличение ХП (1d8 + мод. Телосложения) и +1 к характеристике при повышении уровня

#### 2.1.4. Классы персонажей

##### Воин (V1)
- Высокий запас ХП
- Владение любым оружием и доспехами
- Умение "Второе дыхание" (восстановление ХП 1 раз в день)

##### Маг (V1)
- Заклинания: Огненный шар, Магическая стрела, Щит
- Ограниченные слоты заклинаний
- Зависимость от Интеллекта для силы заклинаний

##### Паладин (V1)
- Лечение и благословения
- Дополнительный урон нежити
- Высокая устойчивость к магии

#### 2.1.5. Инвентарь и предметы
- **Слоты инвентаря:** Упрощённая система (ограниченное количество)
- **Типы предметов:**
  - Оружие (мечи, посохи, луки)
  - Броня (кожа, кольчуги, латы)
  - Зелья (лечение, мана)
  - Свитки (разовые заклинания)
- **Магические свойства:** +1, +2 к атаке/защите
- **Вес предметов:** Упрощённая система (без перегруза в MVP)

### 2.2. Интерфейс пользователя

#### 2.2.1. Макет экрана
```
┌──────────────────────────────────────────────────────────────┐
│ Карта подземелья (60x30)                            │ Статус │
│                                                    │─────────│
│                                                    │  ХП:    │
│                                                    │  Уровень│
│                                                    │  Опыт   │
│                                                    │  AC     │
│                                                    │         │
│                                                    │Инвентарь│
│                                                    │─────────│
│                                                    │ Меч     │
│                                                    │ Щит     │
│                                                    │ Зелье   │
│                                                    │         │
└────────────────────────────────────────────────────┴─────────┘
```

#### 2.2.2. Элементы UI
- **Карта:** Основное игровое поле
- **Панель статуса:** ХП, уровень, опыт, AC
- **Панель инвентаря:** 6 слотов с иконками
- **Контекстное меню:** Всплывающее при выборе действия

#### 2.2.3. Управление
- **Движение:** WASD / Стрелки
- **Действия:**
  - `G` — Подобрать предмет
  - `I` — Открыть/закрыть инвентарь
  - `A` — Атака (затем выбор цели мышью)
  - `M` — Использовать магию/способность
  - `Esc` — Меню (сохранение, выход)
- **Мышь:** Выбор цели, взаимодействие с интерфейсом

### 2.3. Технические системы

#### 2.3.1. Генерация уровней
- **Алгоритм:** Клеточные автоматы
- **Параметры:** Размер, заполненность, гладкость
- **Объекты:** Автоматическое размещение комнат, коридоров, врагов, сундуков
- **Связность:** Гарантия проходимости уровня

#### 2.3.2. Сохранение игры
- **Формат:** JSON сериализация
- **Данные:** Состояние персонажа, карта, инвентарь, позиция
- **Слоты:** Одно сохранение в MVP, множественные в V1

#### 2.3.3. Система модификаций
- **Язык:** Lua 5.4
- **Область воздействия:** Генерация уровней, параметры монстров, предметы
- **API:** Доступ к основным игровым объектам через C# bindings
- **Безопасность:** Изолированное выполнение скриптов

## 3. Нефункциональные требования

### 3.1. Технические требования

#### 3.1.1. Производительность
- **FPS:** Стабильные 60 FPS на средних системах
- **Загрузка уровней:** < 2 секунд
- **Память:** < 500 MB RAM
- **Размер билда:** < 100 MB

#### 3.1.2. Совместимость
- **ОС:** Windows 10+ (первичная), Linux/Mac через .NET
- **Разрешение:** Поддержка стандартных разрешений (1920x1080, 1280x720)
- **Ввод:** Клавиатура + мышь (обязательно).

#### 3.1.3. Надёжность
- **Краши:** Не более 1 критического краша на 10 часов геймплея
- **Сохранения:** 100% надёжность сохранения/загрузки
- **Обработка ошибок:** Грамотные сообщения об ошибках, без потери прогресса

### 3.2. UX/UI требования

#### 3.2.1. Доступность
- **Цветовая схема:** Высококонтрастная (чёрный/белый + акцентные цвета)
- **Управление:** Альтернативные схемы для левшей
- **Текст:** Чёткий, читаемый шрифт (моноширинный)

#### 3.2.2. Удобство использования
- **Кривая обучения:** Новый игрок должен понять основы за 10 минут
- **Справка:** Встроенные подсказки по управлению
- **Обратная связь:** Визуальные/звуковые подтверждения действий

#### 3.2.3. Консистентность
- **Стиль:** Единая визуальная тема (ASCII-эстетика)
- **Управление:** Консистентные горячие клавиши
- **Терминология:** Единый глоссарий терминов D&D

## 4. MVP Scope

### 4.1. Обязательные функции (MVP)

#### 4.1.1. Геймплей
- [ ] Один класс (Воин) с базовыми умениями
- [ ] Один уровень подземелья (генерируемый)
- [ ] 3 типа монстров (Гоблин, Крыса, Скелет)
- [ ] Базовая боевая система (атака, урон, смерть)
- [ ] Система характеристик (6 stats, распределение очков)

#### 4.1.2. Интерфейс
- [ ] Карта 60x30 с отображением объектов
- [ ] Панель статуса (ХП, уровень, опыт)
- [ ] Базовый инвентарь (6 слотов)
- [ ] Управление WASD + мышь

#### 4.1.3. Техническое
- [ ] Генерация уровня клеточными автоматами
- [ ] Система сохранения (одно сохранение)
- [ ] Обработка ввода (клавиатура, мышь)
- [ ] Рендеринг через SadConsole

### 4.2. Исключения из MVP
- ❌ Мультиклассовость
- ❌ Сложные ловушки и головоломки
- ❌ Диалоги и квесты
- ❌ Продвинутая магия
- ❌ Настройка генерации
- ❌ Lua-модификации

## 5. Roadmap

### 5.1. Этап 1: Прототип (2-3 месяца)
- **Цель:** Доказательство концепции
- **Результаты:**
  1. Движущийся персонаж по генерируемому уровню
  2. Базовая боевая система (1 тип врага)
  3. Минимальный UI (карта + статус)

### 5.2. Этап 2: MVP (3-4 месяца)
- **Цель:** Играбельная версия для тестирования
- **Результаты:**
  1. Полный геймплейный цикл (генерация → исследование → бой → смерть)
  2. 3 типа врагов + босс
  3. Система сохранения
  4. Балансировка сложности

### 5.3. Этап 3: V1 (4-6 месяцев)
- **Цель:** Первая полноценная версия
- **Результаты:**
  1. 3 класса (Воин, Маг, Паладин)
  2. 5 уровней с нарастающей сложностью
  3. Финальный босс
  4. Расширенная система предметов (+1, +2)
  5. Множественные сохранения

### 5.4. Этап 4: Долгосрочное развитие
- **Цель:** Расширение и сообщество
- **Направления:**
  1. Lua API для модификаций
  2. Тематические уровни (пещеры, руины)
  3. Дополнительные классы и враги
  4. Система достижений
  5. Поддержка сообщества (форум, документация)

## 6. Критерии приёмки

### 6.1. Технические критерии
- [ ] Сборка проходит без ошибок
- [ ] FPS стабильно 60+ на тестовой системе
- [ ] Потребление памяти < 500 MB
- [ ] Сохранение/загрузка работает корректно
- [ ] Нет утечек памяти после 1 часа игры

### 6.2. Геймплейные критерии
- [ ] Новый игрок может завершить первый уровень за 15-30 минут
- [ ] Смерть ощущается справедливой (не из-за багов)
- [ ] Прогрессия персонажа ощутима
- [ ] Реиграбельность: 3+ различных прохождения возможны

### 6.3. UX критерии
- [ ] Управление интуитивно (без чтения мануала)
- [ ] Интерфейс не мешает геймплею
- [ ] Цветовая схема различима при дневном свете
- [ ] Мышь и клавиатура работают согласованно
