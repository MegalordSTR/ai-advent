# Dungeon Crawler: Console Descent - Видение проекта

## 1. Проблема

### 1.1. Боли целевой аудитории
- **Ностальгия по классическим roguelike** (NetHack, DCSS) с архаичным управлением и графикой
- **Отсутствие доступа к настольным D&D** для многих игроков из-за сложности правил, необходимости группы и времени
- **Разрыв между глубиной тактики и современным UX** — желание иметь тактическую сложность D&D с интуитивным интерфейсом

### 1.2. Кто страдает
- Фанаты настольных ролевых игр, которые не могут регулярно играть в полноценные D&D-сессии
- Игроки roguelike, уставшие от устаревшего интерфейса классических игр жанра
- Любители тактического геймплея, ищущие реиграбельные игры с прогрессией персонажа

## 2. Целевая аудитория

### 2.1. Primary User
- **Демография:** Мужчины 25-35 лет
- **Опыт:** Знакомы с компьютерными играми, ценят реиграбельность и тактическую глубину
- **Мотивация:** Желание погрузиться в мир D&D-подобных механик без сложности полных правил

### 2.2. Сегменты
1. **Фанаты D&D и настольных RPG** — основная аудитория, ищут цифровую альтернативу
2. **Игроки roguelike** — ценят процедурную генерацию и перманентную смерть
3. **Стратегические геймеры** — интересуются тактикой боя и построением билдов

### 2.3. Портрет пользователя
- **Имя:** Алекс, 28 лет
- **Профессия:** IT-специалист
- **Игровые привычки:** Играет в Dungeon Crawl Stone Soup 2-3 раза в неделю, читает /r/roguelikes
- **Боль:** Хочет более плавный интерфейс и современный UX при сохранении тактической глубины
- **Цель:** Пройти подземелье с интересным билдом персонажа, экспериментируя с механиками

## 3. Решение

### 3.1. Ключевые механики
1. **Пошаговый геймплей** — каждое действие (ход, атака, использование предмета) занимает один "такт"
2. **Упрощённые правила D&D 3.5** — базовые броски атаки/урона/спасброски, переосмысленные черты (feats)
3. **Процедурная генерация** — клеточные автоматы для создания уникальных уровней
4. **Тактический бой** — система бросков кубиков, влияние характеристик, позиционирование на сетке
5. **Прогрессия персонажа** — развитие через уровни, выбор черт, улучшение характеристик

### 3.2. Технологический стек
- **Язык:** C# (.NET 10+)
- **Графическая библиотека:** SadConsole (консольная графика с поддержкой цвета, мыши, анимации)
- **Архитектура:** Модульная, с поддержкой Lua-скриптов для модификаций

### 3.3. Интерфейс и UX
- **Вид:** Top-down, сетка 60x30 ячеек
- **Панели:** Карта, инвентарь, статус персонажа
- **Управление:** WASD/стрелки + мышь для выбора целей
- **Дизайн:** ASCII-псевдографика с цветовым кодированием

## 4. Уникальность

### 4.1. Отличия от конкурентов
| Аспект | Dungeon Crawler: Console Descent | Классические roguelike | Современные roguelike |
|--------|-----------------------------------|------------------------|------------------------|
| **Правила** | Упрощённые D&D 3.5 | Собственные сложные системы | Упрощённые/кастомные |
| **Графика** | ASCII + современный UX (SadConsole) | Чистый ASCII | Пиксель-арт/тайлы |
| **Интерфейс** | Мышь + клавиатура, цветные панели | Только клавиатура | Современный GUI |
| **Модификации** | Lua-скрипты, кастомизация генерации | Ограниченные | Часто поддерживаются |

### 4.2. Ценностное предложение
> **"Классическая глубина D&D в современной оболочке"** — сочетание тактической сложности настольных RPG с доступным интерфейсом и реиграбельностью roguelike.

## 5. Метрики успеха

### 5.1. Ключевые показатели
- **Качество:** Положительные отзывы от тестеров (основная метрика)
- **Удовлетворённость:** Время сессии > 30 минут, повторные прохождения
- **Технические:** Стабильность FPS > 60, отсутствие критических багов

### 5.2. Бизнес-модель
- **Продукт:** Бесплатный с возможностью пожертвований
- **Монетизация:** Донаты через Patreon/другие платформы
- **Расширение:** Модификации, созданные сообществом

## 6. Ограничения

### 6.1. Технические
- Зависимость от SadConsole (обновления библиотеки)
- Необходимость знания C# для разработки
- Производительность при больших уровнях (60x30+)

### 6.2. Лицензионные
- Использование механик D&D 3.5 (безопасно по OGL)
- Использование названий классов (воин, маг, паладин) — безопасно
- Оригинальные названия монстров/предметов

### 6.3. Ресурсные
- Время разработки (нет жёстких сроков)
- Команда: соло-разработчик + тестеры

## 7. Стейкхолдеры

### 7.1. Прямые
- **Разработчик** — создание и поддержка игры
- **Тестеры** — обратная связь, балансировка
- **Игроки** — конечные пользователи

### 7.2. Косвенные
- **Сообщество roguelike** — распространение, рецензии
- **Стримеры** — продвижение, геймплейные видео
- **Рецензенты** — обзоры, оценка качества

### 7.3. Контекст
- **Тип проекта:** Личный (не коммерческий)
- **Цель:** Создание качественного продукта для нишевой аудитории

## 8. Горизонт развития

### 8.1. MVP (Minimum Viable Product)
- **1 класс** (базовый воин)
- **1 уровень** подземелья
- **Базовый бой** (атака, урон, здоровье)
- **Инвентарь** (простые предметы)
- **Генерация:** Клеточные автоматы (без тематики)

### 8.2. V1 (Первая полноценная версия)
- **3 класса:** Маг, Воин, Паладин
- **5 уровней** подземелья
- **Финальный босс** на 5-м уровне
- **Система сохранения** игры
- **Расширенный инвентарь** (оружие/броня +1, +2)

### 8.3. Долгосрочное видение
- **Система модификаций** на Lua
- **Тематические уровни** (пещеры, руины, подземелья)
- **Кастомизация генерации** (параметры алгоритмов)
- **Расширенная система черт** (feats)
- **Дополнительные классы и враги**
